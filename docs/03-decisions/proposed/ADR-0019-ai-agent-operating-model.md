# ADR-0019: AI Agent Operating Model

**Status:** Proposed  
**Date:** 2026-05-10  
**Deciders:** TBD

## Context

`.github/agents/cinturon360-v5-planner.agent.md` is the only agent configuration in the repository. It encodes the v5 design rules as a Claude Code agent prompt. No other agents are defined and no policy governs what AI agents are permitted to do within the repository.

The project is currently developed with Claude Code as the primary AI coding assistant. This raises operational questions:

- What can an agent do autonomously (write code, create files, run tests) vs what requires human review?
- How are v5 "hard rules" (`v5-plan.md §2`) enforced for agent-generated code?
- How should agents interact with sensitive resources (secrets, production databases, Stripe live mode)?
- When `.github/workflows/` is created, can CI agents act on PRs automatically?

As AI-assisted development becomes standard practice, having explicit rules prevents accidental rule violations (e.g., an agent introducing a `Class1.cs` stub, or an agent bypassing the architecture layer rules).

The migration document (`claude-migration-to-v5.1.md`) was itself generated by an AI agent during a read-only inspection pass — demonstrating the utility of agents for discovery and documentation tasks.

## Decision

*Not yet decided.* The decision must specify:

1. **Agent types and permitted actions:**

   | Agent Type | Permitted | Requires Human Review |
   | --- | --- | --- |
   | Discovery/read-only | Read all files, produce reports | No |
   | Code authoring | Write/edit source, tests, docs | Yes — all PRs |
   | Migration execution | Run `dotnet ef migrations add`, `psql` against dev | Yes — review migration SQL first |
   | Production ops | Never | Always |

2. **Hard rules agents must never violate** (inherited from `v5-plan.md §2`):
   - Never write to production databases.
   - Never use live Stripe keys.
   - Never commit without tests for new logic (once ADR-0016 coverage targets are set).
   - Never bypass ArchUnitNET layer boundary rules.
   - Never amend a published commit.

3. **Agent identity in git history:** All AI-assisted commits should carry `Co-Authored-By: Claude <...>` to maintain transparency.

4. **Agent file locations:**
   - Agent prompts: `docs/14-ai-agents/` (per the planned Obsidian structure).
   - Agent configuration: `.github/agents/` (current location for the planner agent).

5. **Review of agent-generated ADRs and documentation:** This ADR file and the full ADR backlog were generated by an AI agent. Human review and approval is required before any proposed ADR is moved to `accepted/`.

## Consequences

**If this ADR is accepted:**

- Relocate `.github/agents/cinturon360-v5-planner.agent.md` to `docs/14-ai-agents/claude-code/v5-planner.md` (with a redirect shim if the `.github/agents/` path is used by tooling).
- Update the planner agent prompt to reference v5.1 rules (rebase from `v5-plan.md`).
- Add a `docs/14-ai-agents/operating-model.md` summarising the rules from this ADR.
- Add a CI check that flags any commit where the author is a known AI agent identity without a human co-author.

**Required follow-up:**

- Define the approved Claude Code model versions for agent runs (to prevent unintended model upgrades in automated contexts).
- Document the process for escalating from AI-proposed to human-accepted for each ADR type.
- Review and update the planner agent prompt to reflect v5.1 architecture decisions.
